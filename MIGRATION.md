# Совместимость со старым Kit

Новая версия — обычные Markdown-инструкции. Она не обновляет прежние подключения и не преобразует их форматы. Существующий проект можно оставить как есть.

## Что продолжает работать

В режиме снимка manifest/lock `0.2` проект читает собственные `AGENTS.md`, `.ai-rules/RULESET.md`, `.ai-rules/PROJECT_RULES.md` и `.ai-rules/upstream/`. Удаление генератора из Kit не меняет эти файлы. Старые обязательные маршруты сохраняются до отдельного ручного перехода.

Команды `ai-rules.ps1` и `scripts/shared-kit.ps1` в новой версии отсутствуют. Сохранённые в проектах команды со старым путём к checkout больше не запускаются из этого checkout. Для диагностики, старого обновления или необязательного шаблона используйте отдельную историческую копию ниже. Не направляйте старый updater на новую версию.

В экспериментальном shared-режиме `0.1` проект зависит от внешнего `installRoot`, закреплённого выпуска `releases/<releaseId>`, блока `AEK SHARED` в `AGENTS.md` и возможной ссылки `.agents/skills/aek-project-audit`. Сохраняйте сам выпуск, его исходный путь и ссылку. Git SHA восстанавливает исходники Kit, но не приватные файлы проекта и не произвольную локальную сборку выпуска. Новая версия не удаляет установки и не переключает проекты.

## Восстановление прежнего инструмента

Последний исходный SHA перед упрощением:

```text
f8f406a32299cd00d9e15bb032ef286765b20e77
```

Из корня существующей копии Kit создайте **отдельный новый каталог**, не сбрасывая текущую рабочую директорию:

```sh
git clone --no-hardlinks --no-checkout . ../agent-engineering-kit-legacy
git -C ../agent-engineering-kit-legacy checkout --detach f8f406a32299cd00d9e15bb032ef286765b20e77
git -C ../agent-engineering-kit-legacy rev-parse HEAD
```

Если этого объекта нет в локальной истории, получите историю из доверенного origin. Версия доступна также в [GitHub по точному SHA](https://github.com/Dmitryaf/agent-engineering-kit/tree/f8f406a32299cd00d9e15bb032ef286765b20e77). Восстановленный checkout содержит прежние инструкции и инструменты; он не требует возвращать их в новую версию.

В исторической копии, при установленном PowerShell, можно выполнить read-only диагностику, заменив `PROJECT_PATH` реальным путём:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ../agent-engineering-kit-legacy/ai-rules.ps1 status -ProjectRoot PROJECT_PATH
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ../agent-engineering-kit-legacy/ai-rules.ps1 doctor -ProjectRoot PROJECT_PATH
```

Для воспроизведения снимка сохраняйте **его собственный** `source.revision` из manifest/lock, а не подменяйте его приведённым SHA. Исторический updater использует Git-историю для закреплённой версии; изменение manifest и Apply остаются отдельными действиями. Сначала прочитайте README восстановленной версии и план, не применяйте обновление только ради проверки.

## Переход одного проекта, когда он потребуется

1. Сохраните приватную резервную копию `AGENTS.md`, всей `.ai-rules/`, локальных документов и настроек исключения Git. Для shared-проекта сохраните также выпуск, descriptor и цель ссылки Skill. Убедитесь, что копия читается и позволяет восстановить исходные пути. Git Kit не содержит эти данные; игнорирование файла не является резервной копией.
2. В существующем проектном `AGENTS.md` оставьте команды, ограничения и ссылки на действующие решения. Сначала можно оставить ссылки на прежние `PROJECT_RULES.md` и проектные документы, убрав из них только обязательное подключение общей политики. Учтите исключения из `RULESET.md` и дополнительные локальные инструкции: они могут содержать уникальные решения.
3. Замените старую цепочку CORE/INDEX/профилей на локальный контекст, проверьте все пути. Не переносите приватный контекст в публичный README или отслеживаемый `AGENTS.md`. Общие личные предпочтения объединяются отдельно по [README](README.md).
4. Откройте новую сессию Codex в проекте. Проверьте доступность команд и нужных решений без старой цепочки. До этого оставьте старые файлы и резервную копию. Удаление старого снимка, блока shared или ссылки Skill — отдельное действие после проверки отсутствия потребителей.

Для работы над обычным кодом срочная миграция не нужна. Свежий clone публичного проекта не восстановит игнорируемые инструкции и решения: их нужно вернуть из приватной копии с нужными правами. Отсутствующий контекст следует назвать, а не выдумывать.
