# Node service: настройки качества

Подходит небольшому Node-сервису на TypeScript с нативными ESM. Для выбранного серверного фреймворка, монорепозитория, другого runtime или уже настроенного проекта сохраните его обычные средства. Материал не задаёт HTTP-фреймворк, БД, DI, очередь, мониторинг или развёртывание.

## Как применить

1. Объедините нужные части [tsconfig.json](tsconfig.json) и [eslint.config.mjs](eslint.config.mjs) со своими. [package.example.json](package.example.json) даёт пример зависимостей и команд с npm. Выбор package manager принадлежит проекту.
2. При `NodeNext` относительные импорты TypeScript используют расширение итогового файла `.js`; сборка выдаёт `dist/`. Не переносите сюда `Bundler` из клиентского приложения.
3. Блок `src/logic/**` — необязательный пример запрета платформенного доступа из чистых решений. Укажите фактическую область или удалите блок. Тесты этой области могут использовать Node runner. Новые алиасы, баррели и пакеты внешнего доступа требуют уточнения запретов; материал не является полным анализатором зависимостей.
4. Выполните `npm run check`: типы, линтер, сборка и встроенный Node test runner. В CI можно использовать ту же команду после воспроизводимой установки по lockfile. CI, запуск production и эксплуатационные механизмы выбираются отдельно по задаче.

Демонстрационный HTTP-сценарий существует только в тесте материала. Не копируйте его как готовый сервер. Повторы внешних действий, хранение, отказ БД, восстановление и безопасность данных требуют проверок реального сценария сервиса.

## Версии и сопровождение

Проверяемая среда — Node 22.17.0 (22.13+ в этой линии), npm 11.19.0, TypeScript 5.9.3, ESLint 10.8.0, типы Node 22.15.30 и typescript-eslint 8.65.0. Для воспроизведения используйте npm 11, указанный в package. Это проверяемый пример, не обязательные версии будущего проекта. Другая major-версия или Node-линия требуют проверки. Нативный тестовый runner не добавляет отдельный фреймворк; он ищет скомпилированные `.test.js`, поэтому устаревший выход сборки не должен оставаться после переноса тестов.

Из корня Kit: `node tests/templates/test-technical-materials.mjs` устанавливает зависимости в собственные временные каталоги, проверяет оба материала, успешное и ошибочное вычисление, HTTP-ответ через loopback, отказ неверного типа и запрещённых импортов. `--offline` ограничивает установку npm cache. Проверка не меняет рабочие продукты и не запускает внешнее развёртывание.

После применения конфигурация и lockfile принадлежат проекту; синхронизация Kit их не меняет. При обновлении материала повторите прямой тест и проверьте изменения зависимости. Форматтер, hooks и инфраструктура CI не включены автоматически.

Основания: [TypeScript module resolution](https://www.typescriptlang.org/tsconfig/moduleResolution.html), [Node test runner](https://nodejs.org/api/test.html), [typescript-eslint](https://typescript-eslint.io/getting-started/), [ограничения импортов ESLint](https://eslint.org/docs/latest/rules/no-restricted-imports). Ограничение динамической загрузки проверяется отдельным правилом синтаксиса.
