# Vue/Vite: настройки качества

Подходит новому клиентскому Vue-приложению на TypeScript, когда нужны проверка SFC, тесты независимых вычислений и сборка. Для Nuxt, SSR, другого frontend-стека или существующей настроенной системы выберите её штатные средства. Материал не задаёт страницы, состояние, хранение, дизайн или структуру всех возможностей.

## Как применить

1. Создайте основу штатными средствами Vue/Vite или используйте существующую. Примените нужные части [tsconfig.json](tsconfig.json), [eslint.config.mjs](eslint.config.mjs) и [vite.config.mjs](vite.config.mjs), сохраняя настройки проекта.
2. [package.example.json](package.example.json) содержит команды и точные прямые версии проверяемого примера. Объедините нужные зависимости со своими, выполните установку выбранным package manager и сохраните lockfile по правилам проекта. Это пример с npm, а не обязательный менеджер.
3. Замените `src/logic/**` на реальную границу чистых вычислений или удалите этот блок, если граница не нужна. Не создавайте каталог ради настройки. Это ограничение импортов, не полный анализ графа: новые алиасы, баррели и внешние библиотеки требуют своего контракта и негативных примеров.
4. Выполните `npm run check`. В CI достаточно этой же команды после воспроизводимой установки зависимостей, если CI нужен в задаче. Workflow, hooks и деплой не создаются материалом.

Линтер проверяет TypeScript и SFC. Vitest использует Node environment для чистой логики; DOM-взаимодействия, браузерные состояния, accessibility и качество дизайна проверяются отдельно подходящим инструментом. `vue-tsc` проверяет SFC, Vite собирает их. Форматтер не включён: сохраните принятый или добавьте нужный независимо.

## Версии и сопровождение

Проверяемая среда — Node 22.17.0 (зависимости требуют 22.13+ в этой линии), npm 11.19.0, TypeScript 5.9.3, Vue 3.5.43, Vite 7.3.6, Vitest 4.1.11, ESLint 10.8.0. Для воспроизведения используйте npm 11, указанный в package; npm 10 не входит в проверенную комбинацию. Остальные точные версии — в примере package. Это совместимая комбинация, не рекомендация выбирать старую версию вместо подходящей актуальной. Другая major-версия или Node-линия требуют проверки.

Из корня Kit: `node tests/templates/test-technical-materials.mjs` проверяет оба материала на временных проектах: типы, SFC, тесты логики, сборку, разрешённые импорты и отказ статического импорта, реэкспорта и динамического загрузчика. `--offline` использует только npm cache. Зависимости, полученный lockfile и выход сборки остаются во временной среде; тест не меняет подключённые продукты.

После применения настройки принадлежат проекту. Обновление Kit не обновляет их. При изменении примера проверяйте его совместимость прямым запуском; транзитивные версии закрепляются lockfile конкретного проекта. Для долговременного повторения проверки сохраняйте её временный lockfile как локальное свидетельство, а не добавляйте в Kit ещё одну матрицу стеков.

Основания: [Vite](https://vite.dev/guide/), [TypeScript module resolution](https://www.typescriptlang.org/tsconfig/moduleResolution.html), [typescript-eslint](https://typescript-eslint.io/getting-started/), [ограничения импортов ESLint](https://eslint.org/docs/latest/rules/no-restricted-imports). Эти документы объясняют инструменты; фактическую комбинацию проверяет тест.
