# Правила работы агента

## Что читать

Перед работой прочитай по порядку:

1. `.ai-rules/RULESET.md`;
2. `.ai-rules/PROJECT_RULES.md`;
3. `.ai-rules/upstream/CORE.md`;
4. `.ai-rules/upstream/INDEX.md`;
5. все записи с видом `profile` из `INDEX.md`;
6. только нужные для задачи записи с видом `rule` или `workflow`;
7. связанные с задачей документы, код и тесты проекта.

`INDEX.md` показывает, что и когда читать. Не считай его источником истины. Точный состав и версию правил определяют `.ai-rules/manifest.json`, `.ai-rules/lock.json` и команда `ai-rules.ps1 status`.

Читай выбранный профиль целиком. Не читай весь каталог `.ai-rules/upstream/` и все темы без связи с задачей.

Пути к документации проекта указаны в `.ai-rules/PROJECT_RULES.md`. По индексу и заголовкам найди нужную область, прочитай её разделы карты проекта и записи решений, затем связанные источники. Не читай всю карту или каталог `docs/` для узкой задачи.

## Где менять правила

Не редактируй `.ai-rules/upstream/` вручную. Общие правила меняются в хабе, правила проекта — в `.ai-rules/PROJECT_RULES.md`, явные отступления — в `.ai-rules/RULESET.md`.

Сохраняй этот файл короткой точкой входа. Не копируй сюда сами правила, спецификации и проектную документацию.

## Подключение хаба

Во время подключения можно менять только `AGENTS.md`, локальные файлы `.ai-rules/` и управляемую копию правил.

Не меняй несвязанные код, документацию, автоматические проверки, лицензию или настройки. Найденный разрыв запиши в `RULESET.md`. Исправляй его только в отдельной задаче с согласованными границами.

## Документация

Перед созданием документа прочитай подключённое правило документации по `INDEX.md`: оно определяет аудиторию, каноническое место, хранение и публикацию. Название файла и наличие шаблона сами по себе не требуют его создания или публикации.

## Общие действия

Перед изменениями проверь `git status` и сохрани несвязанные изменения. Для средней или большой задачи веди короткий план с одним активным пунктом.

Выполняй проверки из `.ai-rules/PROJECT_RULES.md`. Не выполняй `commit`, `push`, выпуск, публикацию, переписывание истории или удаление данных без отдельного явного разрешения владельца.
