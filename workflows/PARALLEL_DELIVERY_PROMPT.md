# Запуск параллельной доставки

Используйте этот запрос в Codex, открытом в корне целевого проекта. Добавьте после него описание своей задачи. Команда печатает только текст и не подключает правила автоматически.

## Готовый запрос

```text
Выступи координатором задачи в проекте "{{PROJECT_ROOT}}". Мою задачу я добавлю после этого запроса. Используй Agent Engineering Kit из {{HUB_CLI_PATH}} и рабочий процесс `parallel-delivery` только если параллельная работа действительно полезна.

1. Прочитай локальный `AGENTS.md`, выбранные правила через `.ai-rules/upstream/INDEX.md` и относящийся к задаче код. Проверь `git status`, ветку, несвязанные изменения и состояние подключения Kit. Сначала сформулируй общий наблюдаемый результат и проверки. Если задача короткая или зависимая, работай одним агентом без подключения процесса.
2. Для действительно делимой задачи проверь выбор `parallel-delivery` в manifest и объяснение в RULESET. Проверь также, доступны ли тематические правила `ai-collaboration` и `git-and-delivery` для этой задачи. Если нужного элемента нет, покажи точные изменения локальных manifest и RULESET, план синхронизации и необходимые разрешения. Не меняй управляемые файлы вручную; остановись перед неразрешённым `-Apply`. После применения проверь `doctor` и `status` и прочитай подключённый workflow целиком.
3. Построй граф зависимостей с состояниями `blocked`, `ready`, `parallelizable`, `integration-only`. Найди общие контракты, их источники истины и владельцев. Если контракт новый, определи его до запуска зависимых исполнителей. Подготовь короткие контракты подзадач по шаблону "{{TASK_CONTRACT_PATH}}": владелец, точная база, область записи, зависимости, общие контракты, критерии, проверки и полномочия.
4. Предложи безопасный набор параллельных исполнителей, назначь каждому пишущему агенту отдельную ветку и workspace/worktree и назначь одного владельца интеграции. Передай исполнителю его контракт и нужные локальные инструкции, а не весь свой внутренний контекст. Используй штатные средства Codex (Agent Command Center) для координации, если они доступны; не создавай собственный менеджер агентов.
5. До запуска проверь, что задачи и действия охвачены моим запросом и локальными правилами. Остановись только перед действиями, требующими отдельного невыданного разрешения. Сбор результатов, независимая проверка по риску, интеграция и общий набор проверок выполняются по `PARALLEL_DELIVERY.md`. Исполнители не отправляют изменения и не интегрируют их самостоятельно.

В итоге покажи граф задач, владельцев и рабочие каталоги, результаты и отклонения, итоговую проверенную ревизию, проверки и оставшиеся риски. Не выполняй commit, push, merge, PR, выпуск или публикацию без соответствующего разрешения.
```
