# Подключение проекта

Используйте этот запрос в ИИ-агенте, открытом в корне подключаемого проекта. Путь к команде хаба уже указан в запросе.

## Готовый запрос

```text
Подключи этот проект к Agent Engineering Kit через {{HUB_CLI_PATH}}.

Действуй по шагам:
1. Проверь `git status`, локальные инструкции, основные точки входа, настройки и команды проверки. Сохрани несвязанные изменения владельца.
2. Выбери минимальный набор профилей и тем. Объясни выбор простыми словами и назови точные идентификаторы для `-Profiles` и `-Topics`. Не добавляй правило только потому, что оно есть в хабе. Для нового развиваемого проекта без архитектурного контракта предложи явно выбрать `architecture-and-data` и `project-bootstrap` (тему архитектуры не дублируй, если она входит в профиль). Для существующего проекта отсутствие контракта зафиксируй как разрыв, без автоматического добавления bootstrap.
3. Если `.ai-rules/manifest.json` отсутствует, выполни `connect -ProjectRoot "{{PROJECT_ROOT}}"` с выбранными `-Profiles` и `-Topics`. Если проект уже подключён, выполни эту команду без изменения состава правил.
4. Покажи созданные локальные файлы, предложенную версию хаба и файлы правил, которые будут добавлены или изменены. Для public-repository проверь локальный Git exclude и tracked-инфраструктуру. AGENTS.md, .ai-rules/ и .local/ по умолчанию local-only; приватный путь не записывай в tracked-файлы. Укажи Private Project Context или его отсутствие; уникальные правила после clone восстанавливаются из выбранного приватного версионируемого источника. Потенциально внутренние документы требуют проверки аудитории, а намеренно публичные ADR допустимы. Отдельно скажи, что останется нетронутым.
5. Остановись перед `-Apply` и запроси одно явное разрешение на применение показанных изменений.
6. После разрешения повтори ту же команду с `-Apply`. Проверь результат командами `doctor` и `status`, затем покажи `git diff` проекта. Установи, могут ли форматтер, линтер и поиск тестов захватить установленные файлы Kit. Git ignore не исключает их из этих инструментов. Если нужно исключение в настройках проекта, покажи узкое изменение отдельно; не исправляй неизменяемый выпуск Kit и не выключай проверки исходников проекта.
7. Для нового проекта укажи следующий отдельный шаг: `{{HUB_CLI_PATH}} prompt bootstrap -ProjectRoot "{{PROJECT_ROOT}}"` вместе с целью и первым сценарием. Подключение не создаёт skeleton, guard и не реализует продукт. Последующая разработка начинает с первоначального выбора по архитектурному правилу даже без установленного процесса.

Не выходи за эти границы:
- не редактируй `.ai-rules/upstream/` вручную;
- не исправляй найденные разрывы проекта во время подключения;
- не выполняй `commit`, `push`, публикацию, удаление или изменение истории без отдельного разрешения;
- при существенной неоднозначности дай одну рекомендацию и задай один конкретный вопрос.

В конце кратко сообщи выбранный набор, созданные и обновлённые файлы, результат проверки, предупреждения и следующий отдельный шаг.
```
