# Завершение подключения и первичная проверка

Используйте после `init` и первого `update -Apply`, если локальные правила ещё нужно уточнить. Повторять после каждого обновления не требуется. Это проверка подключения и доступного контекста; полный аудит запускается отдельно через `prompt deep-audit`.

## Готовый запрос

```text
Заверши подключение Agent Engineering Kit и проверь, можно ли продолжать работу с коротким достоверным контекстом.

Границы задачи:
- можно менять только `AGENTS.md`, `.ai-rules/RULESET.md` и `.ai-rules/PROJECT_RULES.md`;
- остальные файлы используй только для чтения;
- не выполняй commit, push, публикацию, удаление и исправление найденных разрывов;
- сохрани несвязанные изменения владельца.

Этап 1 — завершение подключения:
1. Проверь git status, локальные инструкции, manifest.json и lock.json, затем RULESET.md, PROJECT_RULES.md, CORE.md, INDEX.md и выбранные профили. Читай только темы, нужные для проверки подключения, хранения контекста и полномочий; все установленные темы читать не нужно.
2. Найди существующие точки входа, команды запуска и проверки, места для кода и значимых решений. Читай связанные источники постепенно, без полного обзора кодовой базы.
3. В AGENTS.md оставь маршрут, в PROJECT_RULES.md — особенности и команды, в RULESET.md — выбор, исключения и подтверждённые разрывы. Не копируй общие правила и не создавай карту, ADR, guard или CI ради подключения. Незнакомое отмечай как не установлен / не установлена.
4. Покажи изменения разрешённых файлов и явно сообщи, что подключение завершено. После этого не меняй файлы проекта.

Этап 2 — проверка только для чтения:
5. Если команда хаба доступна, выполни doctor и status. Проверь маршрут чтения, точную закреплённую версию, сохранность локальных правил и отсутствие ручной правки upstream. Для публичного проекта проверь local-only, границу публикации и восстановление уникального контекста.
6. Проверь доступность команд запуска и проверки, существующего размещения кода и существенных ограничений для первого запроса. Отсутствие отдельной карты или guard само по себе не дефект. Код, архитектуру и похожие сценарии изучай глубже только при конкретном сигнале риска; полный аудит не входит в подключение.
7. Для значимых пунктов используй `satisfied`, `gap`, `not applicable` или `unknown` с подтверждением. Найденные проблемы отделяй от неизвестного. Остальные проверки запускай только если они не меняют исходные файлы и не оставляют временные данные.

Кратко покажи результат подключения, изменённые файлы, предупреждения и неизвестное. При необходимости укажи отдельные задачи на исправление, но не выполняй их. Новый проект без основы начинает с prompt bootstrap; существующий продолжает свою работу без автоматического рефакторинга.
```

Точные английские статусы сохраняют совместимость прежних отчётов; остальной текст — на языке проекта.
