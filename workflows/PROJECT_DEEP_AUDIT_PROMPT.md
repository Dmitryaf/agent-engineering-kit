# Запуск глубокого аудита проекта

Используйте этот запрос в ИИ-агенте, открытом в корне целевого проекта. Он подключает рабочий процесс только при необходимости, сохраняет отдельное разрешение на применение правил и затем запускает аудит в режиме чтения.

## Готовый запрос

```text
Подготовь и проведи глубокий аудит проекта "{{PROJECT_ROOT}}" через {{HUB_CLI_PATH}}.

Действуй по шагам:
1. Проверь `git status`, локальные инструкции и состояние подключения Agent Engineering Kit. Сохрани несвязанные изменения владельца.
2. Проверь, выбран ли идентификатор `project-audit` в `.ai-rules/manifest.json` и объяснён ли он в `.ai-rules/RULESET.md`.
3. Если идентификатор отсутствует, покажи точные изменения этих двух локальных файлов и остановись до разрешения. После разрешения внеси только показанные изменения, выполни обычный план обновления и снова остановись перед `-Apply`.
4. После отдельного разрешения на `-Apply` синхронизируй правила и проверь результат командами `doctor` и `status`. Не редактируй `.ai-rules/upstream/` или `.ai-rules/lock.json` вручную.
5. Если `project-audit` уже синхронизирован, не меняй состав правил. Полностью прочитай `.ai-rules/upstream/workflows/PROJECT_DEEP_AUDIT.md` и примени его к цели: найти критические проблемы доступной реализации проекта.
6. Сам аудит выполняй только для чтения. Не исправляй находки, не меняй файлы, индекс Git или историю, не выполняй внешние действия.

В результате покажи контракт аудита, сверку опорного инвентаря с картой, подтверждённые проблемы, реестр покрытия, неизвестное, непроверенные области, ограничения и следующие наиболее ценные проверки.
```
