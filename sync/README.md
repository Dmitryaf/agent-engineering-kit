# Низкоуровневая синхронизация

Обычному пользователю этот документ не нужен. Для подключения и обновления правил используйте корневой [`README.md`](../README.md) и команду [`ai-rules.ps1`](../ai-rules.ps1).

Этот документ описывает внутренний контракт синхронизации для разработки и отладки хаба.

## Модель

```text
локальная копия Agent Engineering Kit
→ .ai-rules/manifest.json
→ просмотр изменений
→ явное применение
→ .ai-rules/lock.json и .ai-rules/upstream/
```

После применения проект использует собственную копию правил и не зависит от доступности хаба.

`project-bootstrap` — необязательный идентификатор рабочего процесса в существующем массиве `topics`. Он не меняет manifest/lock schema и не добавляется профилями. Для нового развиваемого проекта его можно выбрать явно; `prompt bootstrap` также позволяет прочитать процесс прямо из хаба. `connect` и `update` управляют теми же файлами правил, не создают архитектурный skeleton или guard и не меняют код проекта.

`visual-design-discovery` — отдельный workflow для существенного нового UI или редизайна. Его можно читать [прямо из хаба](../workflows/VISUAL_DESIGN_DISCOVERY.md) либо явно выбрать через `-Topics`; профили его не устанавливают. Обязанность раннего выбора остаётся в теме `product`, даже если workflow не выбран. Добавление допустимого ID совместимо с существующими manifest/lock `0.2`, миграция старых проектов не нужна; новый ID требует версии Kit, в каталоге которой он уже есть. Подключение не запускает редизайн.

## Файлы проекта

| Файл                         | Владелец      | Назначение                            |
| ---------------------------- | ------------- | ------------------------------------- |
| `AGENTS.md`                  | проект        | Короткая точка входа для агента       |
| `.ai-rules/manifest.json`    | проект        | Выбранные профили, темы и версия хаба |
| `.ai-rules/RULESET.md`       | проект        | Причины выбора и исключения           |
| `.ai-rules/PROJECT_RULES.md` | проект        | Особенности проекта                   |
| `.ai-rules/lock.json`        | синхронизация | Точный состав и контрольные суммы     |
| `.ai-rules/upstream/`        | синхронизация | Установленная копия общих правил      |

Синхронизация меняет только `.ai-rules/lock.json` и `.ai-rules/upstream/`. Остальные файлы принадлежат проекту.

### Публичный проект и Private Project Context

При `public-repository` все перечисленные файлы — локальная инфраструктура, а не обязательная публичная конфигурация. `init` и первая подготовка `connect` устанавливают исключения до создания файлов; `sync -Mode Apply` поддерживает их при обновлении. `Plan`, `status`, `doctor` и `local-only` без `-Apply` не записывают exclude. Профиль берётся из manifest, а не определяется через GitHub API. Для private-проектов поведение хранения не меняется.

Kit дописывает управляемый блок в локальный `info/exclude`, найденный через Git common directory (включая worktree). Блок применяется ко всем worktree этого Git-репозитория:

```text
# BEGIN agent-engineering-kit
/.ai-rules/
/AGENTS.md
/.local/
# END agent-engineering-kit
```

Пользовательские записи сохраняются; блок располагается последним, повторное применение не меняет файл. Идентичные пользовательские записи без отрицательных правил не дублируются. При наличии отрицаний Kit оставляет завершающее исключение в своём блоке. Повреждённые или повторяющиеся маркеры требуют ручного исправления. Публичный `.gitignore` не меняется; его явные отрицательные правила могут перекрыть exclude, поэтому `status` проверяет фактическое игнорирование. Без Git checkout исключения не создаются. Подкаталог другого checkout не принимается за самостоятельный корень публичного проекта. После смены профиля Kit не удаляет прежние исключения автоматически; владелец может удалить блок явно.

**Private Project Context** задаётся по [контракту документации](../rules/DOCUMENTATION.md#приватный-источник-публичного-проекта). Kit не создаёт источник и не синхронизирует его через сеть. Владелец хранит там долгоживущие внутренние документы и уникальные локальные правила. Минимальный путь — сохранить `AGENTS.md`, `RULESET.md`, `PROJECT_RULES.md`, manifest и lock в выбранной структуре приватного источника. `upstream/` хранить не требуется: он производен от чистой версии Kit и manifest; lock фиксирует состав и контрольные суммы.

Необязательный `.ai-rules/private-context.json` — локальная ссылка для агента и диагностики, отдельная от manifest/lock версии `0.2`:

```json
{
  "schemaVersion": "0.1",
  "project": "public-project-identity",
  "source": "<absolute path to the owner's private context checkout>",
  "recovery": "<where an authorized owner restores the versioned source>"
}
```

Это пример, а не готовая конфигурация. `project` явно идентифицирует публичный проект; `source` — выбранный владельцем внешний каталог; `recovery` объясняет восстановление с нужным доступом без токенов. Descriptor создаётся владельцем вручную только после проверки, что `.ai-rules/` исключён и не tracked. Каноническая связь и порядок восстановления также хранятся в приватном источнике: потерянный descriptor не должен делать источник невосстановимым. Приватный путь не копируется в публичную документацию; Kit не печатает содержимое descriptor в диагностике.

`Private context: configured` означает валидный descriptor и доступный внешний каталог, `not configured` — descriptor отсутствует, `unavailable` — descriptor некорректен или источник недоступен. Каталог внутри публичного checkout и путь через reparse point не принимаются за внешний источник. Диагностика не устанавливает приватность сервиса, наличие истории, резервное хранение или фиксацию новых записей. Эти требования проверяет владелец; `configured` не означает «контекст сохранён». Отсутствие источника даёт предупреждение и не блокирует обычную разработку.

После нового clone:

1. Восстановите отдельно локальную копию Kit и выбранный приватный источник с нужными правами доступа.
2. Повторите локальный `connect` с `public-repository` и нужным составом. Если уникальных правил нет, можно применить стартовый набор через `connect -Apply`.
3. Если они есть, до применения восстановите из приватного источника локальные `AGENTS.md`, `.ai-rules/RULESET.md`, `.ai-rules/PROJECT_RULES.md`, manifest и lock. Повторная подготовка не восстанавливает уникальное содержимое шаблонами.
4. Для точного восстановления используйте чистый checkout Kit на `source.revision` из manifest и `plan` / `apply`. Недостающий `upstream/` материализуется из этой версии; сохранённый lock проверяет состав и SHA-256. Для намеренного обновления используйте `update` / `update -Apply`.
5. Восстановите локальный descriptor, выполните `doctor` и `status`. Не копируйте внутренние документы в публичное дерево ради доступности агенту.

### Переход существующего публичного проекта

```powershell
.\ai-rules.ps1 local-only -ProjectRoot C:\path\to\project
.\ai-rules.ps1 local-only -ProjectRoot C:\path\to\project -Apply
```

Первая команда показывает план; вторая только устанавливает блок exclude. Обе диагностируют tracked-инфраструктуру и дают отдельную команду `git --literal-pathspecs rm --cached -r --ignore-unmatch -- AGENTS.md .ai-rules .local`. Выполняйте её из корня целевого проекта только после сохранения уникального контекста, проверки staged/working diff и отдельного разрешения владельца. Она прекращает отслеживание, сохраняя рабочие файлы; при конфликте index Git может отказать — не добавляйте `-f` автоматически. Затем проверьте staged diff. Commit и push остаются отдельными действиями. Старые коммиты и опубликованные артефакты остаются публичными; эта процедура не очищает историю и не гарантирует устранения прошлого раскрытия.

Диагностика разделяет tracked-инфраструктуру, потенциально внутренние документы и явно публичные записи решений с `visibility: repository`. Для Markdown проверяется содержимое index: `visibility: private` — явная проблема физической границы, даже если рабочая копия уже изменена. Имена `DECISIONS.md`, `PROJECT_MAP.md`, `decisions/`, `docs/adr/`, `architecture/` — повод определить аудиторию, а не автоматическое нарушение. Kit не скрывает пользовательские каталоги и не выполняет общий security scan.

## Подготовка проекта

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File scripts/init-project-sync.ps1 `
  -ProjectRoot C:\path\to\project `
  -Profiles standard-product `
  -SeedProjectFiles
```

Команда создаёт недостающие локальные файлы, но не применяет общие правила и не перезаписывает существующие файлы проекта.

## Просмотр изменений

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File scripts/sync-rules.ps1 `
  -ProjectRoot C:\path\to\project `
  -Mode Plan
```

Режим `Plan` ничего не записывает. Проверьте пути и состояния в выводе.

| Состояние         | Значение                                     |
| ----------------- | -------------------------------------------- |
| `add`             | файл будет добавлен                          |
| `update`          | файл будет обновлён                          |
| `unchanged`       | файл уже совпадает                           |
| `conflict`        | файл изменён вручную; применение остановится |
| `orphan`          | файл больше не выбран, но сохранён           |
| `orphan-modified` | исключённый файл изменён вручную             |
| `orphan-missing`  | исключённый файл уже отсутствует             |

## Применение

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File scripts/sync-rules.ps1 `
  -ProjectRoot C:\path\to\project `
  -Mode Apply
```

Режим `Apply` требует:

- полный SHA коммита в `source.revision`;
- чистую рабочую копию хаба;
- отсутствие состояния `conflict`.

Для первого применения используйте корневую команду `update -Apply`: она закрепляет текущую версию хаба перед записью.

Запись выполняется как одна операция. При обработанной ошибке существующие файлы восстанавливаются, а созданные этой попыткой файлы и пустые каталоги удаляются. После аварийного завершения процесса проверьте `git diff` перед повтором.

Локальный exclude для публичного профиля устанавливается отдельно перед материализацией правил и сохраняется при ошибке sync; защита локальных файлов не откатывается. Сам exclude записывается через временный файл и атомарную замену, чтобы ошибка записи не обрезала пользовательские правила.

Хаб не удаляет исключённые файлы автоматически. Удалять их можно только после проверки ссылок и отдельного разрешения владельца.

## Проверка подключения

```powershell
.\ai-rules.ps1 status -ProjectRoot C:\path\to\project
.\ai-rules.ps1 doctor -ProjectRoot C:\path\to\project
```

`status` показывает краткое состояние и следующий шаг. `doctor` подробно проверяет локальные файлы, маршруты, контрольные суммы и согласованность выбранного набора.

Текстовые файлы проверяются после приведения окончаний строк к LF и кодировки к UTF-8 без BOM. Бинарные файлы проверяются обычной контрольной суммой SHA-256.

## Формат версии 0.2

`manifest.json` хранит выбранные `profiles`, `topics` и `source.revision`. `lock.json` хранит установленную версию, состав, пути, состояния и SHA-256 каждого файла.

Путь назначения обязан находиться внутри `.ai-rules/upstream/`. Путь через символическую ссылку, соединение каталогов или другую точку перенаправления файловой системы отклоняется до записи.

Корневые sync-файлы вида `.ai-*.json` автоматически не переносятся. Их появление останавливает подготовку и требует отдельного явного переноса.

Идентификатор `project-study` сохранён для совместимости, но теперь указывает на `workflows/PROJECT_STUDY.md`. Старый файл остаётся в состоянии `orphan` до ручной проверки и удаления.

## Ограничения

Хаб не выполняет удалённую загрузку правил, массовое обновление проектов, автоматическое объединение конфликтов, `commit`, `push` или публикацию.

### Локальная проверка ещё не зафиксированных правил

Обычный `update -Apply` по-прежнему требует чистый checkout. Если владелец явно поручил применить локальные изменения без commit, сначала просмотрите `update`, затем используйте `update -Apply -AllowDirtySource`. Это явное исключение только для локального снимка: manifest указывает базовый commit, lock сохраняет `source.dirty: true` и фактические SHA-256. Один commit SHA не восстанавливает такой снимок; до разрешённой фиксации сохраняйте рабочую копию Kit. Конфликты управляемых файлов по-прежнему останавливают Apply. Низкоуровневый `scripts/sync-rules.ps1` принимает тот же флаг; неизвестное состояние Git не разрешается.
