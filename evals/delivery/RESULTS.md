# Результат delivery-пилота Phase 1

Общая установка работоспособна: проект использует закреплённый выпуск, постоянный блок CORE и выбранные материалы без локального `upstream`. После исправления маршрута наблюдалось чтение `SKILL.md → references/workflows/PROJECT_DEEP_AUDIT.md`. Эти данные подтверждают доступность доставки в проверенных условиях; превосходство shared и надёжность автоматического discovery не установлены.

## Условия

Канонический SHA обеих сторон: `3d0987449f3a50a363b3de7b44d8a30d7924d650`. Нормализованные хеши выбранных CORE/profile/topics/workflow проверены до каждой попытки. Задачи, синтетические файлы, локальные правила и грязный `OWNER_NOTES.md` совпадают внутри каждой пары. Снимок использует существующий CLI из чистой ревизии, shared — новый adapter; это предусмотренная переменная эксперимента.

Native CLI: `codex-cli 0.158.0`; одинаково настроенные `gpt-6-sol`, `xhigh`, `--ignore-user-config`, `--ephemeral`, sandbox `read-only`, approval `never`. Фактический model ID события не раскрывают. Авторизация используется штатно, credentials не читались и не копировались. Глобальные инструкции, доступные инструменты, cache и политика среды остаются внешними факторами.

В первом запуске шесть попыток были отклонены до работы: настроенный alias `gpt-6.1-sol` не поддерживался native CLI с текущей авторизацией. Следующий запуск на `gpt-6-sol/high` завершался с отказами чтения в трёх попытках режима снимка и shared-аудите; две shared-задачи прочитали материалы. Эти отказы не считаются оценкой качества недоступного кода.

Контрольный запуск добавил во все задачи одинаковое ограничение одиночного чтения через `rg -n`, без указания прочитать CORE или конкретную тему. Из настроек к этому времени был получен `xhigh`; поэтому улучшение между запусками нельзя приписать только способу чтения. Внутри каждой сравниваемой пары настройки одинаковы. Исходные отказы и журналы завершённых запусков сохранены отдельно; артефакты подготовительных ошибок и прерванного запуска также оставлены приватными. Прерванный запуск не считается завершённым наблюдением.

## Ограничения поведения

Оба режима применяют audit workflow частично: есть область, инвентарь, поиск опровержений, сквозная находка, таблица покрытия и существенное неизвестное. Полный предварительный контракт, явная связка inventory → map IDs и вся структура отчёта не отражены. Успешное чтение не означает полное выполнение процесса.

В попытках режима снимка контрольного запуска не наблюдался `git status`; shared выполнял его. Контекст был избыточным в обоих режимах: первый снимок прочитал целиком PRODUCT/ARCHITECTURE, shared-аудит перечитывал несколько правил. Последний shared-аудит также прочитал больше норм, чем достаточно для маленькой фикстуры. Нативный сигнал выбора metadata Skill не предоставлен; наблюдается реальное чтение по нативному project-пути, а не доказательство внутреннего алгоритма автоматического discovery.

Один контрольный запуск на сценарий и один повтор исправленного audit route не дают причинного доказательства качества, экономии или автономной надёжности. Повторный audit — отдельная пара, не замена первого наблюдения. Единый score не вычислялся.

Project-owned local documents и исходные файлы в первый ряд не входят; directory link считается одним узлом, а не копией файлов Skill. У shared отдельно есть общая установка. По две команды preview/Apply использовались для подключения обеих сторон в harness; shared дополнительно установил один общий выпуск. Подсказка чтения — дополнительное участие экспериментатора, поэтому обычная работа без неё пока не доказана.

Точные наблюдаемые input/cached/output tokens, elapsed time, хеши ответов и canonical files сохранены в [results.json](results.json). Это отдельные метрики; из них не выводится стоимость в деньгах или общий выигрыш. Raw commands, stderr, ответы, global guidance hashes и локальные пути остаются под `.local-docs/delivery-eval/` и не опубликованы в этом отчёте. Проверку выполнили агенты реализации по журналам; review владельца остаётся отдельным действием.

## Детерминированные проверки

Исторический catalog regression воспроизведён до исправления. Проверены новый SHA с другой composition, dirty catalog при прежнем SHA, недоступная история и сохранение проверки установленного lock. Новая версия рядом со старой, pin существующего проекта и выбор для нового, повреждение выпуска, missing installation, отсутствие автоматического fallback, local ownership и публичный index проверены fixtures.

Полный Windows PowerShell 5.1 suite: 10 наборов, 1730 assertions. Полный PowerShell 7 suite до последней изолированной коррекции маршрута: 1729; обновлённый shared suite после неё: 65. Команды: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/test-tooling.ps1`, соответствующий запуск через `pwsh`, `scripts/check-hub.ps1`, `git diff --check`. Применимые проверки прошли; результаты не являются проверкой production-проекта или другой агентской среды.

Следующий минимальный шаг — один явно выбранный новый проект на проверенной среде с устойчивым доступом чтения: проверить обычную работу без экспериментальной подсказки и соблюдение полного audit report contract. Массовая миграция этим пилотом не обоснована.
