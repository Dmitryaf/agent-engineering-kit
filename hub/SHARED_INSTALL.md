# Экспериментальная общая установка: Phase 1

Один локальный неизменяемый выпуск обслуживает несколько проектов через Codex. Проект получает управляемый блок `AGENTS.md`, `.ai-rules/shared.json` и, при явном выборе `project-audit`, ссылку на Skill. Общие правила не копируются в проект. Это отдельный экспериментальный режим; существующие `ai-rules.ps1 connect/update/plan/apply` работают со снимком как прежде.

## Использование

Из checkout Kit с чистыми, закоммиченными каноническими источниками:

```powershell
# Установить выпуск отдельно от подключаемых проектов.
.\scripts\shared-kit.ps1 install -InstallRoot C:\AgentKit -Apply

# Подключить новый проект; профиль standard-product выбран по умолчанию.
.\scripts\shared-kit.ps1 connect -InstallRoot C:\AgentKit -ProjectRoot C:\Projects\Example -Apply

# Проверить подключение, затем открыть новую сессию Codex в проекте.
.\scripts\shared-kit.ps1 doctor -ProjectRoot C:\Projects\Example
```

Без `-Apply` установка, подключение и выбор выпуска только показывают план. `-SourceRoot` позволяет установить канонические материалы из другого чистого локального checkout. Обновлять локальные правила ради установки не требуется: их путь задаёт `-LocalRules`, по умолчанию `.ai-rules/PROJECT_RULES.md`. Инструмент не создаёт и не переписывает этот проектный документ; отсутствие отражается в диагностике. Команды и локальные ограничения остаются ответственностью проекта.

Для проекта, которому нужен глубокий аудит, при подключении явно добавьте `-Topics project-audit`. Несколько идентификаторов можно передавать массивом PowerShell или через запятую. `-Profiles standard-product,public-repository` включает локальные Git excludes; index и историю это не меняет. Проверяйте предупреждения перед публикацией. Private Project Context сохраняет прежний отдельный контракт и не создаётся автоматически.

После подключения запросите обычную работу в новой сессии Codex. Для аудита явно назовите цель и область и попросите применить `project-audit`. Skill сам по себе не разрешает аудит, запись отчёта или исправления.

## Выпуск и закрепление

```text
installation/
  selected.json
  releases/r-<source SHA prefix>-<bundle digest prefix>/
    release.json
    bootstrap.md
    adapter.json
    rules/, profiles/, workflows/, templates/, sync/
    skills/aek-project-audit/SKILL.md
    skills/aek-project-audit/references/...

project/
  AGENTS.md                         # generated block + прежний проектный текст
  .ai-rules/shared.json              # schema 0.1, mode shared, policy pinned
  .ai-rules/PROJECT_RULES.md          # принадлежит проекту
  .agents/skills/aek-project-audit    # только при явном выборе: directory link
```

`release.json` хранит полный Git SHA канонических источников, их хеши, хеши генератора и файлов поставки. Digest охватывает эту identity; имя выпуска содержит её префиксы. Незакоммиченные изменения генератора допустимы и различаются через builder hashes; их нельзя выдавать за часть canonical SHA. Нормализация переводов строк соответствует существующей проверке SHA-256 Kit. `install` не перезаписывает существующий выпуск, проверяет его целостность и сохраняет старые выпуски. Неизменяемость обеспечивается контрактом инструмента и обнаружением изменений; файловый ACL или цифровая подпись не устанавливаются. Запущенная задача должна использовать закреплённый путь; внешняя порча файлов диагностируется.

Установка выбирает выпуск для **новых подключений**. Выбор можно изменить отдельно:

```powershell
.\scripts\shared-kit.ps1 select -InstallRoot C:\AgentKit -ReleaseId r-0123456789ab-0123456789abcdef0123 -Apply
```

Используйте фактический ID из `install`. Уже подключённые проекты остаются закреплёнными, включая новые сессии в них. Phase 1 не переподключает существующий проект к другому выпуску. Сохранённый старый выпуск можно выбрать для нового подключения; миграция и repin требуют отдельного решения. Отсутствующая или повреждённая установка не вызывает автоматического перехода к снимку.

## Постоянные инструкции и Skill

`adapters/codex/adapter.json` выбирает точные разделы `CORE` для постоянного блока: контекст, Git, границы задачи, факты, недоверенные данные, обратимость, контроль владельца, проверка и честная передача. Фрагмент генерируется из источника; нормативные предложения не пересказываются вручную. Остальной CORE и выбранные профили читаются по маршруту, тематические материалы — по задаче. Недоступный или неоднозначный выбранный раздел останавливает сборку.

`skills/project-audit.json` содержит только metadata и путь к `workflows/PROJECT_DEEP_AUDIT.md`. Установщик генерирует `SKILL.md` и переносит точный канонический workflow с нормативными ресурсами в `references/`. Их хеши сверяются с источниками. Прямые зависимости аудита замкнуты внутри Skill; административные ссылки на установку, репозиторий и инфраструктуру evals остаются справочными и не расширяют разрешённые действия. Подключение снимка из канонического workflow явно неприменимо к shared-режиму. Нормативные каталоги остаются единственными редактируемыми источниками.

Для выбранного `project-audit` точка входа ведёт через `SKILL.md` к его относительному ресурсу. Конкурирующий прямой маршрут к workflow в AGENTS не генерируется: поведенческий пилот выявил обход ресурсов Skill при наличии двух путей к одному тексту.

Часть для Codex — `AGENTS.md`, `.agents/skills`, directory junction на Windows и проверки discovery/override. Сборка выпуска и хеши не требуют нового agent runtime. Других adapters в Phase 1 нет.

## Диагностика и ограничения

`status` и `doctor` выводят JSON: `requested` — закреплённый выбор проекта, `installed` — проверенный выпуск, `available` — только доступность файлов, `loaded` — `unknown`. Установка не доказывает discovery, право инструмента читать внешнюю директорию или чтение агентом. Эти факты оцениваются по реальным сессиям. Ошибки установки или управляемого блока дают ненулевой exit code; предупреждения о локальных правилах и публикации сохраняются отдельно.

Проект с manifest снимка отклоняется без автоматического перехода. Локальные правила и текст AGENTS вне блока сохраняются; изменённый управляемый блок, устаревший план, сторонний каталог Skill и корневой `AGENTS.override.md` останавливают Apply. Перед записью выполняется повторная проверка плана; это не распределённая блокировка конкурентных редакторов.

Phase 1 хранит происхождение генератора, но не запускает builder-код из выпуска. Проверка блока использует текущий adapter. Будущая смена его формата потребует явного решения о совместимости; корректность старого подключения нельзя молча восстанавливать другим текстом. Текущая версия инструментов проверяется тестами; совместимость произвольных будущих генераторов не обещается.

Нативная документация Codex описывает [AGENTS hierarchy](https://learn.chatgpt.com/docs/agent-configuration/agents-md) и [project Skills discovery](https://learn.chatgpt.com/docs/build-skills). Объединённые инструкции имеют ограничение размера; adapter отклоняет проектный AGENTS сверх стандартных 32 KiB. Глобальные и вложенные инструкции могут влиять на итоговую сессию и не покрываются этим измерением. После изменения подключения нужна новая сессия. Поддержанный минимум — Windows PowerShell 5.1 и Git; junction требует доступной локальной файловой системы. Длинные пути Windows и ограничения sandbox могут мешать установке или чтению. Выбирайте короткий локальный InstallRoot и проверяйте доступ из целевой среды. Unix symbolic-link ветка остаётся экспериментальной.

## Проверка Phase 1

Детерминированные проверки: [`test-shared-install.ps1`](../tests/cli/test-shared-install.ps1) и [`test-historical-catalog.ps1`](../tests/diagnostics/test-historical-catalog.ps1). Полный suite включает прежний режим снимка. Историческое раскрытие состава теперь читает catalog закреплённого SHA; недоступная история и незакоммиченные исторические источники остаются явно неизвестными.

Парный поведенческий эксперимент описан в [`evals/delivery/README.md`](../evals/delivery/README.md). Он сравнивает один canonical SHA, одинаковые задачи и настройки Codex. Подготовка fixtures отдельно от API запуска; actual loading и успех проверяются по наблюдениям, без единого score. Результат пилота публикуется отдельно от нормативных правил.

[Результат пилота](../evals/delivery/RESULTS.md) подтверждает чтение bundled workflow после устранения конкурирующего прямого маршрута. Он также сохраняет отказы среды, подсказку чтения и неполное выполнение формы аудита; превосходство shared не установлено.
